# Installing Tailscale on PetaLinux and Other Minimal / Obscure Linux Systems

This guide explains how to install Tailscale on Linux systems where the normal Tailscale installer does not recognize the operating system.

It is primarily intended for:

- PetaLinux
- Yocto-based systems
- Buildroot
- Vendor-specific embedded Linux
- Custom Linux distributions
- Minimal Linux appliances
- Systems without `apt`, `dnf`, `yum`, `opkg`, or `apk`
- Systems without `/etc/os-release`

The procedure was tested on:

```text
PetaLinux
Architecture: aarch64 / ARM64
Kernel: 5.4.0
```

Tailscale provides static Linux binaries specifically for distributions that are not covered by its normal installation script.

---

# 1. Understand the Problem

On a normal Linux distribution, Tailscale can usually be installed with:

```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

The installer detects the Linux distribution and selects the appropriate package manager.

For example:

```text
Ubuntu     → apt
Debian     → apt
Fedora     → dnf
RHEL       → dnf/yum
openSUSE   → zypper
```

However, embedded Linux systems may look like:

```text
Linux 5.4.0
aarch64
```

without providing:

```text
/etc/os-release
```

or a package manager.

In that situation the installer may report:

```text
Couldn't determine what kind of Linux is running.

OS=other-linux
VERSION=
PACKAGETYPE=

No /etc/os-release
```

This does **not** mean Tailscale cannot run on the system.

It means the automatic package-based installer cannot determine how to install it.

The solution is to use Tailscale's **static binaries**.

---

# 2. Check the System

Before installing anything, determine the architecture:

```bash
uname -a
```

For ARM64/PetaLinux you will typically see:

```text
aarch64 aarch64
```

You can also run:

```bash
uname -m
```

Expected:

```text
aarch64
```

Common architecture mappings:

| `uname -m` | Tailscale binary |
|---|---|
| `x86_64` | `amd64` |
| `aarch64` | `arm64` |
| `armv7l` | `arm` |
| `riscv64` | `riscv64` |
| `mips` | `mips` |
| `mips64` | `mips64` |

Tailscale currently publishes static binaries for architectures including AMD64, ARM, ARM64, MIPS, MIPS64, and RISC-V 64.

Check available package/binary information here:

[Tailscale stable packages and static binaries](https://pkgs.tailscale.com/stable/?utm_source=chatgpt.com)

---

# 3. Check Internet Connectivity

First check whether the device can reach the Internet.

For example:

```bash
ping 8.8.8.8
```

If that works but:

```bash
ping tailscale.com
```

doesn't, you probably have a DNS problem.

Check:

```bash
cat /etc/resolv.conf
```

For a temporary DNS test:

```bash
echo "nameserver 8.8.8.8" > /etc/resolv.conf
```

Then:

```bash
ping tailscale.com
```

> Note: `/etc/resolv.conf` may be generated by your embedded system. A manually written file may therefore be temporary.

---

# 4. Check HTTPS / CA Certificates

Embedded Linux systems frequently have an outdated or incomplete CA certificate bundle.

Test:

```bash
curl -Iv https://pkgs.tailscale.com/
```

If you get:

```text
SSL certificate problem:
unable to get local issuer certificate
```

but:

```bash
ping 8.8.8.8
```

works, your Internet connection is probably fine.

The problem is TLS certificate verification.

---

# 5. Check the CA Bundle

Look for:

```bash
ls -l /etc/ssl/certs/ca-certificates.crt
```

If it exists, test it explicitly:

```bash
curl \
  --cacert /etc/ssl/certs/ca-certificates.crt \
  -Iv \
  https://pkgs.tailscale.com/
```

A successful result should contain:

```text
SSL certificate verify ok.
```

and:

```text
HTTP/1.1 200 OK
```

---

# 6. If the CA Bundle Is Outdated

If the embedded system doesn't have a package manager, obtain a current CA bundle from another trusted machine.

For example, on a normal Linux system:

```bash
curl -o ca-certificates.crt https://curl.se/ca/cacert.pem
```

Copy it to the embedded device:

```bash
scp ca-certificates.crt root@<DEVICE-IP>:/etc/ssl/certs/ca-certificates.crt
```

Before replacing an existing bundle, make a backup:

```bash
cp \
  /etc/ssl/certs/ca-certificates.crt \
  /etc/ssl/certs/ca-certificates.crt.backup
```

Then test:

```bash
curl \
  --cacert /etc/ssl/certs/ca-certificates.crt \
  -Iv \
  https://pkgs.tailscale.com/
```

---

# 7. Tell curl Which CA Bundle to Use

Some embedded builds of curl don't automatically discover the expected CA bundle.

Check:

```bash
curl -V
```

Then test:

```bash
export CURL_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt
```

Verify:

```bash
curl -Iv https://pkgs.tailscale.com/
```

You should see:

```text
successfully set certificate verify locations:
* CAfile: /etc/ssl/certs/ca-certificates.crt
```

followed by:

```text
SSL certificate verify ok.
```

This environment variable is particularly useful because programs launched from the shell can inherit it.

---

# 8. Do NOT Use `-k` as the Permanent Solution

You may be tempted to do:

```bash
curl -k https://tailscale.com/install.sh
```

`-k` disables TLS certificate verification.

It can be useful as a diagnostic:

```bash
curl -kIv https://pkgs.tailscale.com/
```

If this works while normal curl fails, you've confirmed that the TLS trust store is the problem.

However, don't use `-k` as the permanent installation method.

The correct solution is to fix the CA trust configuration.

---

# 9. Try the Normal Installer Once

After fixing TLS:

```bash
export CURL_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt
```

Try:

```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

On a normal supported Linux distribution this should install Tailscale.

On PetaLinux or another custom distribution, it may instead say:

```text
Couldn't determine what kind of Linux is running.
```

That's expected.

At that point, stop using the installer and switch to the static binary.

---

# 10. Download the Static Tailscale Binary

For ARM64:

```bash
curl -fL \
  https://pkgs.tailscale.com/stable/tailscale_latest_arm64.tgz \
  -o /tmp/tailscale.tgz
```

For other architectures, use the corresponding static archive from:

[Tailscale static binaries](https://pkgs.tailscale.com/stable/?utm_source=chatgpt.com)

Extract it:

```bash
tar -xzf /tmp/tailscale.tgz -C /tmp
```

You should get a directory similar to:

```text
/tmp/tailscale_1.102.4_arm64/
```

List its contents:

```bash
ls -lh /tmp/tailscale_*_arm64/
```

It should contain:

```text
tailscale
tailscaled
```

The static archive also contains a systemd service definition, although embedded systems such as PetaLinux commonly don't use systemd.

---

# 11. Install the Binaries

Copy the binaries into the system:

```bash
cp /tmp/tailscale_*_arm64/tailscale /usr/bin/tailscale
cp /tmp/tailscale_*_arm64/tailscaled /usr/sbin/tailscaled
```

Make them executable:

```bash
chmod +x /usr/bin/tailscale
chmod +x /usr/sbin/tailscaled
```

Verify:

```bash
tailscale version
```

and:

```bash
tailscaled --version
```

Example:

```text
1.102.4
```

At this point the Tailscale userspace is installed.

---

# 12. Check TUN Support

Tailscale requires a TUN device/kernel capability. Tailscale's documentation specifically calls out the `tun` kernel module for Linux installations.

Check:

```bash
ls -l /dev/net/tun
```

A working system may show:

```text
crw-rw-rw- 1 root root 10, 200 /dev/net/tun
```

If it does not exist, check whether the kernel module is available:

```bash
lsmod | grep tun
```

If your system has `modprobe`:

```bash
modprobe tun
```

On a custom PetaLinux kernel, TUN support may need to be enabled in the kernel configuration/build rather than loaded as a module.

---

# 13. Create the Tailscale State Directory

Create:

```bash
mkdir -p /var/lib/tailscale
```

This directory will contain Tailscale's persistent state.

---

# 14. Start `tailscaled`

On systemd-based Linux:

```bash
systemctl enable --now tailscaled
```

But PetaLinux and other embedded systems often don't have systemd.

Start it directly:

```bash
tailscaled \
  --state=/var/lib/tailscale/tailscaled.state &
```

You should see output similar to:

```text
Program starting: ...
Creating WireGuard device...
Bringing WireGuard device up...
Bringing router up...
Engine created.
...
Switching ipn state NoState -> NeedsLogin
```

The important part is that `tailscaled` successfully creates its networking engine.

---

# 15. Authenticate Tailscale

Once `tailscaled` is running:

```bash
tailscale up
```

Tailscale will provide an authentication URL.

Open that URL from another computer and authorize the device.

After authentication:

```bash
tailscale status
```

You can also check:

```bash
ip addr show tailscale0
```

A successful setup should have a `tailscale0` interface and a Tailscale `100.x.x.x` address.

---

# 16. Verify Connectivity

Check:

```bash
tailscale status
```

Then from another machine in the same tailnet:

```bash
ping <tailscale-ip>
```

You can also test SSH:

```bash
ssh root@<tailscale-ip>
```

This is particularly useful for embedded boards that are behind NAT or difficult to reach through the normal LAN.

---

# 17. PetaLinux Example

For a PetaLinux ARM64 board, the complete installation after networking and CA certificates are working is approximately:

```bash
# Tell curl which CA bundle to use
export CURL_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt

# Download static ARM64 Tailscale
curl -fL \
  https://pkgs.tailscale.com/stable/tailscale_latest_arm64.tgz \
  -o /tmp/tailscale.tgz

# Extract
tar -xzf /tmp/tailscale.tgz -C /tmp

# Install binaries
cp /tmp/tailscale_*_arm64/tailscale /usr/bin/tailscale
cp /tmp/tailscale_*_arm64/tailscaled /usr/sbin/tailscaled

# Permissions
chmod +x /usr/bin/tailscale
chmod +x /usr/sbin/tailscaled

# Verify
tailscale version
tailscaled --version

# Verify TUN
ls -l /dev/net/tun

# Create state directory
mkdir -p /var/lib/tailscale

# Start daemon
tailscaled \
  --state=/var/lib/tailscale/tailscaled.state &

# Authenticate
tailscale up

# Verify
tailscale status
```

---

# 18. Make It Start Automatically

The exact method depends on how your embedded Linux image starts services.

Possible mechanisms include:

- systemd
- SysV init
- BusyBox init
- PetaLinux init scripts
- custom vendor startup scripts

If systemd is available:

```bash
systemctl enable --now tailscaled
```

Tailscale's static archive includes a systemd service definition that can be used on systems running systemd.

For PetaLinux without systemd, add the equivalent command to the appropriate startup/init mechanism:

```bash
tailscaled \
  --state=/var/lib/tailscale/tailscaled.state
```

Do not blindly copy a systemd service into a PetaLinux system that doesn't use systemd.

# 19. Troubleshooting

## `Could not resolve host`

Example:

```text
curl: (6) Could not resolve host
```

Check:

```bash
cat /etc/resolv.conf
```

Test raw connectivity:

```bash
ping 8.8.8.8
```

Then test DNS:

```bash
ping tailscale.com
```

If raw IP connectivity works but DNS doesn't, fix DNS first.

---

## `unable to get local issuer certificate`

Example:

```text
curl: (60) SSL certificate problem:
unable to get local issuer certificate
```

Check:

```bash
ls -l /etc/ssl/certs/ca-certificates.crt
```

Test explicitly:

```bash
curl \
  --cacert /etc/ssl/certs/ca-certificates.crt \
  -Iv \
  https://pkgs.tailscale.com/
```

If that succeeds, configure:

```bash
export CURL_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt
```

Then retry the download.

---

## Installer says `OS=other-linux`

Example:

```text
Couldn't determine what kind of Linux is running.

OS=other-linux
VERSION=
PACKAGETYPE=

No /etc/os-release
```

This is common on custom embedded Linux.

Don't keep trying:

```bash
apt install tailscale
```

or:

```bash
opkg install tailscale
```

unless your particular image actually provides those package managers.

Use the static binary instead.

---

## `tailscale` command not found

Check:

```bash
ls -l /usr/bin/tailscale
```

and:

```bash
echo $PATH
```

If necessary:

```bash
/usr/bin/tailscale version
```

---

## `/dev/net/tun` doesn't exist

Check:

```bash
ls -l /dev/net/tun
```

and:

```bash
lsmod | grep tun
```

If `modprobe` exists:

```bash
modprobe tun
```

For PetaLinux, check the kernel configuration and enable TUN support if necessary.

---

## `tailscaled` starts but Tailscale is stopped

You may see:

```text
Switching ipn state NoState -> NeedsLogin
```

followed by:

```text
Tailscale is stopped
```

This can simply mean that `tailscaled` is running but the client has not been authenticated/configured yet.

Run:

```bash
tailscale up
```

---

## Policy routing warnings

On custom embedded kernels you may see:

```text
router: warning: running without policy routing
```

This does not necessarily mean ordinary Tailscale connectivity cannot work.

However, advanced functions such as subnet routing can require additional kernel/networking capabilities.

Test basic Tailscale connectivity first.

---

# 20. Useful Diagnostic Commands

When debugging an obscure Linux installation, collect:

```bash
uname -a
uname -m

cat /etc/os-release 2>/dev/null || echo "No /etc/os-release"

which apt
which apt-get
which dnf
which yum
which opkg
which apk
which systemctl
which modprobe

curl -V

ls -l /etc/ssl/certs/ca-certificates.crt
ls -l /dev/net/tun

tailscale version 2>/dev/null
tailscaled --version 2>/dev/null
```

This quickly tells you:

1. CPU architecture
2. Kernel version
3. Whether the OS identifies itself
4. Which package manager exists
5. Whether systemd exists
6. curl/TLS capabilities
7. CA certificate availability
8. TUN availability
9. Whether Tailscale is installed

# 21. General Rule for "Obscure Linux"

The decision tree is:

```text
                 Start
                   |
                   v
          What architecture?
                   |
          +--------+---------+
          |        |         |
        amd64    arm64    riscv64
          |        |         |
          +--------+---------+
                   |
                   v
        Is the Linux distro supported?
                   |
             +-----+-----+
             |           |
            YES           NO
             |             |
             v             v
       Normal installer   Static binary
       / package manager  installation
             |             |
             +------+------+
                    |
                    v
             Is HTTPS working?
                    |
             +------+------+
             |             |
            YES            NO
             |             |
             |        Fix DNS / CA
             |        certificates
             |             |
             +------+------+
                    |
                    v
              Is TUN available?
                    |
             +------+------+
             |             |
            YES            NO
             |             |
             |       Enable TUN in
             |       kernel/module
             |             |
             +------+------+
                    |
                    v
             Start tailscaled
                    |
                    v
               tailscale up
                    |
                    v
              tailscale status
```

# 22. Key Takeaways

For normal Linux:

```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

For PetaLinux/custom/minimal Linux:

```text
Don't fight the package manager.
Use the static Tailscale binaries.
```

For ARM64:

```bash
tailscale_latest_arm64.tgz
```

Install:

```bash
tailscale
tailscaled
```

Then:

```bash
tailscaled --state=/var/lib/tailscale/tailscaled.state &
tailscale up
```

And verify:

```bash
tailscale status
```

The three things that matter most on an embedded Linux system are:

```text
1. Internet + DNS
2. Valid CA certificates for HTTPS
3. Kernel TUN support
```

# 23. Revert / Remove Tailscale

This section reverts the changes made during the manual Tailscale installation described in this guide.

**No Yocto/PetaLinux rebuild is required.**

### 23.1 Stop Tailscale

First bring Tailscale down:

```bash
tailscale down
```

Then stop `tailscaled`:

```bash
killall tailscaled
```

If `killall` is unavailable:

```bash
kill "$(pgrep tailscaled)"
```

---

### 23.2 Remove Tailscale Binaries

We manually installed:

```text
/usr/bin/tailscale
/usr/sbin/tailscaled
```

Remove them:

```bash
rm -f /usr/bin/tailscale
rm -f /usr/sbin/tailscaled
```

---

### 23.3 Remove Tailscale State

We created:

```text
/var/lib/tailscale
```

Remove it:

```bash
rm -rf /var/lib/tailscale
```

This removes the local Tailscale state and identity from the device.

---

### 23.4 Remove Downloaded Files

Remove the downloaded archive and extracted binaries:

```bash
rm -f /tmp/tailscale.tgz
rm -rf /tmp/tailscale_1.102.4_arm64
```

---

### 23.5 Revert the CA Certificate

During installation we replaced:

```text
/etc/ssl/certs/ca-certificates.crt
```

with a newer CA bundle.

If you created the backup:

```text
/etc/ssl/certs/ca-certificates.crt.backup
```

restore it:

```bash
cp \
  /etc/ssl/certs/ca-certificates.crt.backup \
  /etc/ssl/certs/ca-certificates.crt

rm -f /etc/ssl/certs/ca-certificates.crt.backup
```

If you **didn't create a backup**, don't delete the current CA bundle. Leave it in place.

---

### 23.6 Remove the Temporary curl Setting

We used:

```bash
export CURL_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt
```

Remove it from the current shell:

```bash
unset CURL_CA_BUNDLE
```

Verify:

```bash
echo "$CURL_CA_BUNDLE"
```

It should be empty.

---

### 23.7 Revert DNS Only If You Changed It

We temporarily changed `/etc/resolv.conf` using:

```bash
echo "nameserver 8.8.8.8" > /etc/resolv.conf
```

If you did that and need to restore the original DNS configuration, restore your previous `/etc/resolv.conf`.

If you don't remember what it contained, check whether it is normally managed automatically:

```bash
ls -l /etc/resolv.conf
```

**Do not delete or modify it unnecessarily.**

---

### 23.8 Verify Everything Is Gone

Run:

```bash
pgrep tailscaled
```

No output means `tailscaled` is no longer running.

Check the interface:

```bash
ip link show tailscale0
```

It should report that the interface does not exist.

Check the binaries:

```bash
which tailscale
which tailscaled
```

Both should return nothing.

Check the state:

```bash
ls -ld /var/lib/tailscale
```

It should report that the directory doesn't exist.

### Complete cleanup

For the exact installation performed in this guide, the cleanup is therefore:

```bash
tailscale down 2>/dev/null || true
killall tailscaled 2>/dev/null || true

rm -f /usr/bin/tailscale
rm -f /usr/sbin/tailscaled

rm -rf /var/lib/tailscale

rm -f /tmp/tailscale.tgz
rm -rf /tmp/tailscale_1.102.4_arm64

unset CURL_CA_BUNDLE
```

Then optionally restore the original CA bundle and DNS configuration if you changed them.
